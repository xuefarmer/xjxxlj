## Layered Perception Workflow

### Layer 1: independent event + operated-object state caption for every segment
- The first tool call must be one `observe` call with `MODE=layer1_caption`.
- It must cover every video segment.
- Use the same `num_frames` for every target. Default: 8 frames per target.
- The VLM must describe each video independently. Do not compare clips, do not infer chronology, and do not mention likely order.
- The VLM output must be compact and complete. It must include every requested video exactly once. If there are many clips, prioritize coverage over prose detail.
- Output must be structured per video:
  - event summary: what visible operation is happening, who/what is involved, and whether it looks like preparation, transformation, transfer, cooking, finishing, or inspection;
  - operation flow: source object, destination object, tool/contact, and immediate result when visible;
  - main operated objects: the objects that the action is changing or using, plus relevant secondary objects in the scene;
  - concrete object states using terse phrases: color, shape, texture, whole/cut/mixed, dry/wet, raw/cooked, clean/dirty, full/empty, intact/damaged, separated/combined, residue/transfer;
  - object lifecycle signals: unused/available, being transformed, already transformed, transferred, missing, completed, reset, hard to see;
  - relevant environment/interaction cues, such as heat, motion, contact, tool use, position, or background object state;
  - uncertainty.
- Do not output only an object-state list. The event description is needed to identify which object is being operated on and why that state matters.
- Also do not stop at the event label. If a clip says "mixing", report what is being mixed and its state; if it says "cutting", report what changed shape; if it says "adding", report source object, destination object, and transfer traces. Also report quiet but decisive state clues in the background.

### Focus: detailed verification
- Focus begins only after Layer 2.
- Use the same `num_frames` for every compared target. Default: 12 frames per target. 16 is already plenty for close comparison; never use more than 16.
- Observe only 1-2 targets per focus call.
- The focus prompt must inherit prior confirmed context, name the exact uncertain event relation and object/state dimension, name the comparison reference, and define visual evidence for each possible order.
- Focus prompts must be symmetric. Do not write the prompt as if one order is the default. For each possible order, list realistic visual evidence and ask for contradiction checks.
- Never infer order from an action template alone. A visually "preparatory" action can happen before, during, or after another action. Use the event description to form hypotheses, then verify them through the operated object's state chain.
- Focus may backtrack. If a focus result contradicts an earlier caption or scan, re-focus the earlier clip instead of continuing down one path.

## Answer Readiness Check
Before using `answer`:
- The proposed order must include every video index exactly once.
- Count the video indices in `final_answer` before answering. For N videos, it must contain N numbers and the set must be exactly `{1..N}` with no missing, duplicate, or out-of-range index.
- The `thought` must include the event role and visual object-state evidence for every adjacent edge in the proposed order, not only for the most obvious middle/final stages.
- If any adjacent edge lacks direct object-state evidence, call `observe` with `MODE=focus` on that pair before answering.
- Pay special attention to early-stage pairs. They are often less dramatic than cooking/plating clips, but they decide many PSS errors.
- If action semantics suggests an order but object states could contradict it, do not settle it from common sense. Require visible operated-object evidence such as state transformation, position change, depletion, transfer traces, residue, contact marks, completion marks, or caption support.
- If one video has a clear state but no confirmed predecessor/successor, treat it as an orphan clip and focus it against its most plausible neighbor before answering.
- If the evidence forms a dependency graph or partial order, first list every video as placed or unplaced in `thought`. Parallel preparation clips must still be inserted into the final linear sequence; never output only the main chain while dropping a side branch.
- Before finalizing, convert all visible state relations into a dependency graph, then topologically sort it. Do not create an adjacent edge that reverses a state chain already reported by the VLM, such as: noodle-in-water/strainer before noodle-transfer-to-pan; greens-only pan before noodles-on-greens; red/brown-base-only pan before red/brown mixed into the dish; noodle-transfer/mixing before already-combined final pan.

## Answer Format
- `final_answer` must be a string of numbers and arrows, for example `"3->5->4->2->1"`.
- Do not include "Video" wording or explanations in `final_answer`.
- Before `answer`, the `thought` must explicitly list visual evidence for every key ordering decision.
- A final answer that omits a video, repeats a video, or outputs only a partial chain is invalid.
- A final answer that contains every video but reverses a known state chain is also invalid.

## Common Failure Patterns To Avoid
- Wrong: using different frame counts for videos in the same comparison layer.
- Wrong: using Layer 1 captions to immediately guess the final order.
- Wrong: accepting generic descriptions like "all are stirring" or "all are cooking".
- Wrong: relying only on action common sense. Object state evidence decides the order.
- Wrong: deleting event descriptions and outputting only object states. The event tells which operation is happening and which objects matter.
- Wrong: describing only the event while omitting the state of the operated object. "Stirring", "cutting", "pouring", or "adding" are not enough; report what changed and what traces were left.
- Wrong: assuming a visually preparatory action must come before another action. Some preparation happens during or after another process, so inspect the operated object's lifecycle state and related traces.
- Wrong: dropping a parallel or orphan preparation clip from the final answer because the main cooking chain is already clear.
- Wrong: overusing `get_caption`. Speech may provide timeline clues but often omits the crucial visual state.
