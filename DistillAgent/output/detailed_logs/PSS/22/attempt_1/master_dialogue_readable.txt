## Unified Workflow
Always solve through four stages:

### Layer1: broad independent perception
Goal: build an unbiased inventory for every relevant video/view/segment.
- First visual call for standard video tasks should usually be `batch_observe` covering all inputs independently. This preserves long-video chunking and broad coverage.
- For standard multi-video tasks, Layer1 should use `batch_observe` unless the task contract explicitly says a side-by-side `observe` is required. Do not replace a full-video chunked scan with one sparse `observe`.
- Use `observe` for Layer1 only when targets must be viewed side-by-side, when the task uses UAV/image-folder frame indices, or when clips are already short enough that one call has adequate coverage.
- For broad standard-video Layer1 scans, set `num_frames = max(16, round(duration_seconds / 5))` unless the task contract says otherwise. The executor will split long windows into chunks of up to 16 frames, so full-video Layer1 chunks should normally run at 16 frames each.
- Ask the VLM to describe each target independently; do not ask it to decide the final answer yet.
- The Layer1 `focus_prompt` must be task-aware: name the query, relevant option semantics, and the evidence dimensions from the task contract.
- Output memory should include:
  - `layer1_done`: true
  - `event_memory`: compact per-target event or scene facts
  - `object_memory`: recurring or decisive objects/entities with per-target states
  - `temporal_index`: target -> useful time/frame windows, each with window, event label, key objects, visible state, why it matters, and confidence
  - `preliminary_answer`: the best current answer/order/table if one can be inferred from Layer1, otherwise null
  - `preliminary_confidence`: integer 1-10 for that preliminary answer, where 8+ means the evidence is already strong enough to consider a direct answer
  - `confidence_basis`: short evidence summary for the confidence score
  - `blocking_uncertainties`: exact missing facts or close alternatives that prevent confidence from reaching 8
  - `irrelevant_windows`: target -> checked windows or whole targets that look irrelevant, with a short reason and coverage note
  - `candidate_targets`: plausible videos/views/segments/options and why
  - `low_value_targets`: high-confidence irrelevant targets and why
  - `uncertain`: unresolved distinctions
  - `dimensions_to_compare`: exact visual dimensions needed next

### Layer2: selective cross-analysis and targeted re-observation
Goal: use Layer1 to avoid wasting VLM calls and build a comparison table.
- Layer2 is normally expected before `answer`, but it is a supplemental verifier rather than a replacement for Layer1 evidence.
- If Layer1 already contains high-confidence, directly visible, decisive evidence for a complete final answer and the close alternatives/relations are explicitly rejected, the controller may answer after Layer1 only when `preliminary_confidence >= 8`. Explain the decisive target/window/table/order evidence and include `confidence_score: N/10` in `thought`.
- Otherwise, run one Layer2 re-check on the plausible candidate(s), close negative(s), or decisive window(s) to verify the conclusion.
- First analyze Layer1 results yourself. Do not blindly send every chunk/video back to the VLM.
- Layer2 may re-check all videos/chunks only when Layer1 leaves every one of them genuinely answer-relevant; then the thought must give a per-video/chunk reason. Otherwise select only the Layer1 chunks whose evidence is missing, conflicting, ambiguous, or capable of changing the answer.
- Carry Layer1's `preliminary_answer`, `preliminary_confidence`, `confidence_basis`, and `blocking_uncertainties` into Layer2. Layer2 should verify or repair the current best hypothesis rather than inventing an unrelated or opposite hypothesis.
- When forming a Layer2/focus hypothesis, start from the current leading answer/edge and the closest explicitly named alternative. Do not choose the reverse relation as the main hypothesis unless Layer1 evidence made that reverse relation plausible.
- Prune targets that are both high-confidence and irrelevant. Keep them in `low_value_targets` with the reason, but do not re-observe them unless a later contradiction appears.
- Re-observe only:
  - plausible candidates;
  - targets with missing decisive state;
  - targets needed as a comparison anchor;
  - edge cases that could change the answer.
- Layer2 must not simply increase frame count. Prefer changing the attention/checklist over adding frames.
- Layer2 must cite the Layer1 evidence or chunk label that caused each target/window to be selected. A Layer2 call that merely repeats the Layer1 full scan without this selection rationale is invalid.
- For standard-video retained targets, use `batch_observe` when re-checking independent videos or long windows. Use `observe` only for side-by-side comparison or short retained windows where direct comparison is needed.
- When Layer2 prunes a few irrelevant chunks from a long video, keep the remaining chunk windows and re-check only those. Do not collapse a long retained video into one sparse 8-12 frame `observe`.
- Use similar or slightly lower frame density than Layer1 for broad retained scans, but preserve chunked coverage. The point is to drop unnecessary chunks, not to stop chunking altogether.
- The Layer2 prompt must include a concrete checklist derived from Layer1, not generic "look carefully" instructions.
- Use Layer1's `temporal_index` to choose retained windows. If Layer1 did not localize a needed event, Layer2 should ask the VLM to produce or refine that index before broad high-frame focus.
- When re-checking a Layer1 chunk, copy the exact seconds from that chunk label. For example, if Layer1 says `[Chunk 2/7 (85s-171s)]`, the Layer2 target must use that same `[85, 171]` window, not the next chunk. If a Layer2 result contradicts Layer1, first verify that the same video and same time window were inspected before overturning Layer1 evidence.
- Do not overturn a high-confidence Layer1 finding using a Layer2 result from a different window, lower-coverage sample, or generic absence statement. Use Layer2 contradictions to refine or request focused verification unless they inspect the same evidence window with stronger direct evidence.
- Required memory update:
  - `layer2_done`: true
  - `comparison_table`: target -> decisive state/evidence/uncertainty
  - `temporal_index`: refined candidate windows with event labels, key objects, visible states, and confidence
  - `irrelevant_windows`: windows or targets excluded from future focus, with reason
  - `confirmed`: high-confidence findings with evidence
  - `pruned_targets`: targets not sent to VLM again, with reason
  - `candidate_targets`: remaining plausible targets
  - `uncertain`: exact unresolved relations or labels
  - `focus_plan`: ranked list of next focus calls with predicted evidence

### Focus Compare: predict -> observe -> reply
Goal: resolve one concrete uncertainty with denser evidence.
- Before each focus call, state a hypothesis and a competing alternative in `thought`.
- Predict what visual evidence should appear for each interpretation.
- Focus only the minimal necessary targets/chunks: usually 1-2 targets, never broad full scans.
- Focus normally uses `observe`, because it compares specific windows side-by-side or inspects one narrow window densely.
- Increase frame density over Layer2 for the same time/window because this is detailed verification:
  - standard video focus: usually 16-32 frames per target;
  - short clips or PSS pair focus: 12-16 can be enough;
  - UAV focus: 24-32 frames per synchronized view when tracking/occlusion matters.
- Narrow the time/frame window. Prefer exact candidate chunks found in Layer1/Layer2 over whole-video focus.
- Every focus call should cite the `temporal_index` window it is using. If no indexed window exists, first use Layer2 or captions to locate one unless the full clip is already very short.
- Focus prompts must be symmetric: define evidence for hypothesis A and evidence for hypothesis B, then ask for contradiction checks.
- Never treat the order of frames in a multi-target `observe` call as chronology across different videos. The executor concatenates frames only for display. Use frame mapping to identify source video/local window, not to decide which video came first.
- If focus contradicts earlier memory, use `MODE=focus BACKTRACK` and update `resolved_uncertain`.
- After focus, update:
  - `confirmed` or `resolved_uncertain`;
  - remaining `uncertain`;
  - `object_memory` / `comparison_table`;
  - whether another focus is needed before answering.

### Answer
Answer only when the decisive evidence is explicit enough for the task.
- You may answer directly after Layer1 only when Layer1 evidence is high-confidence, directly visible, complete for the required final format, no close candidate/relation remains unresolved, and `confidence_score >= 8/10`.
- If answering after Layer1, cite the decisive target/window, option table, interval, or order graph and write `confidence_score: N/10` in `thought`.
- If confidence is 7/10 or lower, or if no numeric confidence is available, do not answer from Layer1; run Layer2/focus.
- Otherwise, run Layer2/focus before answering.
- `thought` must summarize the decisive evidence and explain close rejections.
- `final_answer` must contain only the required answer format from the task contract.
- For multiple-select and ordering tasks, count/check all required indices or letters before answering.

## General VLM Prompt Style
Every visual `focus_prompt` should be short but specific:
- start with mode;
- name the task-specific query;
- name the targets/options being checked;
- list 4-8 decisive visual dimensions;
- ask for uncertainty explicitly;
- avoid asking the VLM for the final answer unless the task is a direct VLM comparison.
- ask the VLM to report approximate time/frame locations for decisive events when it can infer them from frame mapping, so the controller can update `temporal_index`.
- ask for concise key evidence only: task-relevant visible objects/actions/states, approximate time/window, and confidence. Avoid long recipe narration, background details, or speculative cross-video conclusions.
- For a single-video `batch_observe` item, never ask the VLM to decide whether something appears in other videos. Ask only for evidence inside that one video/chunk; the controller compares across videos after all per-video evidence returns.

Good Layer2 wording:
`MODE=layer2. Based on Layer1, re-check only the plausible candidates and refine the temporal_index. For each retained target, fill this checklist: [specific object/state dimensions]. For each decisive event, report the approximate time/frame window if visible. Mark non-visible details using ABSENT, NOT_VISIBLE_IN_THESE_FRAMES, or UNCERTAIN according to the negative-evidence rules. Do not discuss pruned targets.`

Good Focus wording:
`MODE=focus. Hypothesis A: ... Expected evidence: ... Hypothesis B: ... Expected evidence: ... Inspect only [objects/actions/landmarks]. Report which hypothesis is supported, contradicted, or insufficient.`

## Temporal Retrieval Index
Maintain a lightweight retrieval index so later stages focus on specific chunks instead of full videos.
- For standard videos, use seconds: `[start_time, end_time]`.
- For UAV/image-folder tasks, use frame indices: `[start_frame, end_frame]`.
- For PSS, each clipped segment's local time starts at 0; record the local window inside that segment.
- For PSS and other shuffled-video tasks, `temporal_index` windows are local retrieval pointers only. They are not global timestamps and must never be compared across different `video_index` values to infer order.
- Index only useful windows:
  - `candidate_windows`: likely answer-relevant moments;
  - `decisive_moments`: narrow events that could prove/reject an option or ordering edge;
  - `irrelevant_windows`: windows already checked and unlikely to matter.
- Each indexed item should include: target/video/view/segment id, window, event label, key objects/entities, visible state, why it matters, and confidence (`high`, `medium`, or `low`).
- When a VLM result is chunked by executor as "part 2/5, time 88s-176s", preserve that chunk range in `temporal_index` even if the exact event time is approximate.

Example:
```json
"temporal_index": {
  "video2": [
    {
      "window": [72, 96],
      "event": "possible detach/reinstall",
      "key_objects": ["base", "chassis"],
      "visible_state": "part removed then reattached",
      "why_it_matters": "could decide option A",
      "confidence": "medium"
    }
  ]
}
```

## Negative Evidence Rules
Be precise about absence.
- Use `ABSENT` only when the sampled window covers the relevant stage/location and the object/action should be visible if present.
- Use `NOT_VISIBLE_IN_THESE_FRAMES` when the current frames do not show it, but the sampled window may not cover the relevant moment or camera view.
- Use `UNCERTAIN` when the detail would affect the answer and the frames are ambiguous, occluded, blurred, too sparse, or outside the relevant window.
- Do not convert `NOT_VISIBLE_IN_THESE_FRAMES` into a global negative conclusion. If it matters, add a `temporal_index` gap and focus/caption plan.
- If earlier context reported an object/action but current frames do not show it, write `NOT_VISIBLE_IN_THESE_FRAMES - possibly in another indexed window` rather than directly contradicting prior evidence.

## Captions
- Do not call `get_caption` before Layer2.
- Captions are auxiliary for names, timing, dialogue, or step labels.
- Visual state evidence remains primary. If captions and visuals conflict, focus/backtrack visually.
- Captions are unavailable for UAV/image-folder tasks.

## Common Failure Modes To Avoid
- Re-observing every target in Layer2 after Layer1 already ruled some out.
- Using higher frame count in Layer2 instead of a better checklist.
- Using broad focus windows instead of the specific uncertain chunk.
- Selecting an option because it sounds plausible but the option-specific action/state is not visible.
- Treating absent in sampled frames as globally absent without noting possible frame coverage limits.
- Reversing a visible state chain.
- Letting captions replace visual confirmation.

## Task Contract: PSS

- quiet background cues that show before/after state;
- state-transition graph built by the master from local visible rows.

Workflow notes:
- Layer1 scans every segment independently and must not infer final ordering yet. For executor compatibility, PSS Layer1 prompts must begin with `MODE=layer1_caption`.
- Layer1 prompts must ask for object states explicitly, not only event roles. Use wording like: "Describe the operation, visible objects/tools, and each object's state: raw/cooked, fresh/wilted, whole/cut, dry/wet, absent/present, separate/mixed, empty/filled, residue/depletion."

  Example: `{"noodles": {"3": "raw/dry on plate", "2": "boiled soft strands in pan", "1": "mixed with sauce"}, "spinach": {"4": "fresh whole leaves", "2": "wilting with noodles", "1": "mixed into finished dish"}}`.

- For PSS, `order_confidence >= 8` means Layer2 should mostly verify the current graph and close alternatives. `order_confidence <= 7` means Layer2 should actively search for missing object bridges or contradictions.
- Use `event_memory` only as secondary per-video notes. Do not make `object_memory` primarily video-centric, such as `{"video4": {"object": "spinach", "state_chain": [...]}}`; that structure overweights local clip-internal actions and causes wrong ordering.

Layer2 re-observes these linked evidence items at finer granularity to clarify their actual visible state in each segment. For executor compatibility, Layer2 prompts must begin with `MODE=layer2_state_scan`.
- Layer2 is NOT hypothesis confirmation. Do NOT pass the Master's preliminary_order or expected states to the VLM. Ask the VLM to report what is actually visible for each linked evidence item: identity, presence/absence, count, position, state (raw/cooked, empty/filled, clean/dirty), source/destination, residue/depletion, and any difference from what was seen in Layer1.
- Layer1 and Layer2 are mandatory before `answer`. Do not answer directly after Layer1; Layer2 clarifies the shared evidence that bridges segments.
- Layer2 must inherit `preliminary_order`, `order_confidence`, `confidence_basis`, and `blocking_uncertainties` from Layer1 — these guide which evidence to prioritize, but remain internal to the Master and are not shown to the VLM.
- After receiving Layer2 results, perform a contradiction check in `thought`: compare each segment's VLM-reported evidence against the hypothesized state-transition graph. If any evidence contradicts the hypothesized ordering, downgrade `order_confidence` and resolve via focus or caption before answering.

- In Layer2 focus_prompt: do not ask the VLM for ordering, do not use words like "confirm", "verify", "should", or "expected". Ask for local visible evidence only. Example: "Look at this segment. - Focus resolves one adjacent relation or state-chain conflict at a time with higher frame density than Layer2, usually 12-16 frames per compared segment.
- Focus targets must come from `uncertain_visual_states`, `next_object_focus`, object-memory gaps, or contradictions in object states. Do not choose a focus pair merely because it appears adjacent in a guessed answer or because the executor might prefer a focus call.
- Focus prompts must not ask the VLM to decide which segment is earlier, which hypothesis is supported, or whether Video A happens before Video B. Ask for per-target cells only: named object state, container fill/empty state, source/destination, residue/depletion, background object state, and uncertainty. The master compares the cells after the tool returns.
- Do not write expected focus evidence that assumes one proposed order is true, such as "if A is before B, B should already contain X", unless that expectation is explicitly grounded in earlier tool output. Prefer neutral wording: "For each target, report whether object X is ABSENT, EMPTY/CLEAR, PARTLY_FILLED, FILLED_DARK, or NOT_VISIBLE."
- When a focus call is needed, include the current leading relation and current overall order confidence in `thought`, but keep the VLM prompt neutral. Standalone components such as sauce, flame, garnish, dressing, chopping, mixing, and plating may appear in non-obvious positions in the source video.
- If local rows do not give direct visible continuity for a complete total order, call `get_caption` on every segment involved in unresolved ties, using each segment's full local window. Captions are allowed after Layer2 for PSS and may provide spoken step labels, temporal words, or demonstrated ordering. Keep `context_update` empty on caption actions too.

If the focus still cannot prove the edge, mark the tie in `thought`; do not pretend it is proven by recipe logic.

- Do not ask the VLM to decide ordering from "frame-level timestamps" across videos, hypothesized cross-segment orders, or recipe logic. The VLM reports local object states only; cross-segment dependency reasoning is master-only.
- Before answering, form an explicit state-transition graph from `object_memory`, with relations like `A before B: object_key state in A visibly precedes/feeds/contradicts state in B`. List unresolved ties, and run caption/focus for any tie that changes the final order. Then check every segment is placed exactly once.
- The final `thought` must include one overall `confidence_score: N/10`. This is the confidence that the complete final order is correct, not confidence in a single easy relation.
- Calibrate `confidence_score` conservatively: it may be `>=8` only when the complete order is visually supported and no critical relation, object-chain conflict, or close same-role tie remains unresolved. If any necessary relation is based on recipe common sense, a coarse role label, a conflicting object chain, or an unresolved tie, set `confidence_score <= 7` and do not answer; call caption/focus instead.
- Before any final `answer`, include an `ORDER_AUDIT` in `thought` with four fields: `supporting_chains`, `conflicting_chains`, `unresolved_relations`, and `confidence_change`. `confidence_change` must explain why the final score is higher, lower, or unchanged compared with Layer1 `order_confidence`.
- If `conflicting_chains` or `unresolved_relations` is non-empty, the final `confidence_score` must be `<=7` unless a later caption/focus result directly resolves each listed item.
- The final `thought` must also include an `EDGE_TABLE` for evidence audit, but do not assign per-edge confidence scores. Each relation may use one of these evidence types: `direct_transfer`, `same_object_state_progression`, `visible_completion_to_next_start`, `caption_temporal_cue`, or `focused_visual_tie_break`. Do not use evidence types like `recipe_logic`, `common_sense`, `typical_order`, `coarse_role_only`, or `sounds_later`.

Final answer:
- `final_answer` is a string like `"3->5->4->2->1"` containing every segment index exactly once.
