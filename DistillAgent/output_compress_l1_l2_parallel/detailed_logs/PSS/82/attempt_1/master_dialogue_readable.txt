## Unified Workflow
Always solve through four stages:

### Layer1: broad independent perception
Goal: build an unbiased inventory for every relevant video/view/segment.
- First visual call for standard video tasks should usually be `batch_observe` covering all inputs independently. This preserves long-video chunking and broad coverage.
- For standard multi-video tasks, Layer1 should use `batch_observe` unless the task contract explicitly says a side-by-side `observe` is required. Do not replace a full-video chunked scan with one sparse `observe`.
- Use `observe` for Layer1 only when targets must be viewed side-by-side, when the task uses UAV/image-folder frame indices, or when clips are already short enough that one call has adequate coverage.
- For broad standard-video Layer1 scans, set `num_frames = max(16, round(duration_seconds / 5))` unless the task contract says otherwise. The executor will split long windows into chunks to maintain frame density, so full-video Layer1 chunks should normally run at 16 frames each.
- Ask the VLM to describe each target independently; do not ask it to decide the final answer yet.
- The Layer1 `focus_prompt` must be task-aware: name the query, relevant option semantics, and the evidence dimensions from the task contract.
- Output memory should be compact:
  - `layer1_done`: true
  - `event_memory`: only decisive events; one short cell per target
  - `object_memory`: key objects and states only; avoid background inventory
  - `temporal_index`: only useful windows; keep field names `window`, `event`, `key_objects`, `visible_state`, `why_it_matters`, `confidence`, but keep each value short
  - `preliminary_answer`: the best current answer/order/table if one can be inferred from Layer1, otherwise null
  - `preliminary_confidence`: integer 1-10 for that preliminary answer, where 8+ means the evidence is already strong enough to consider a direct answer
  - `confidence_basis`: short evidence labels, not a paragraph
  - `blocking_uncertainties`: exact missing facts only
  - `irrelevant_windows`: id + one short reason
  - `candidate_targets`: id + short reason
  - `low_value_targets`: id + one short reason
  - `uncertain`: unresolved facts only
  - `dimensions_to_compare`: exact visual dimensions, max short phrases

### Layer2: selective cross-analysis and targeted re-observation
Goal: use Layer1 to avoid wasting VLM calls and build a comparison table.
- Layer2 is normally expected before `answer`, but it is a supplemental verifier rather than a replacement for Layer1 evidence.
- If Layer1 already contains high-confidence, directly visible, decisive evidence for a complete final answer and the close alternatives/relations are explicitly rejected, the controller may answer after Layer1 only when `preliminary_confidence >= 8`. Explain the decisive target/window/table/order evidence and include `confidence_score: N/10` in `thought`.
- Otherwise, run one Layer2 re-check on the plausible candidate(s), close negative(s), or decisive window(s) to verify the conclusion.
- First analyze Layer1 results yourself. Do not blindly send every chunk/video back to the VLM.
- Layer2 may re-check all videos/chunks only when Layer1 leaves every one of them genuinely answer-relevant; then the thought must give a per-video/chunk reason. Otherwise select only the Layer1 chunks whose evidence is missing, conflicting, ambiguous, or capable of changing the answer.
- Carry Layer1's `preliminary_answer`, `preliminary_confidence`, `confidence_basis`, and `blocking_uncertainties` into Layer2. Layer2 should verify or repair the current best hypothesis rather than inventing an unrelated or opposite hypothesis.
- When forming a Layer2/focus hypothesis, start from the current leading answer/edge and the closest explicitly named alternative. Do not choose the reverse relation as the main hypothesis unless Layer1 evidence made that reverse relation plausible.
- Prune targets that are both high-confidence and irrelevant. Keep them in `low_value_targets` with the reason, but do not re-observe them unless a later contradiction appears.
- Re-observe only:
  - plausible candidates;
  - targets with missing decisive state;
  - targets needed as a comparison anchor;
  - edge cases that could change the answer.
- Layer2 must not simply increase frame count. Prefer changing the attention/checklist over adding frames.
- Layer2 must cite the Layer1 evidence or chunk label that caused each target/window to be selected. A Layer2 call that merely repeats the Layer1 full scan without this selection rationale is invalid.
- For standard-video retained targets, use `batch_observe` when re-checking independent videos or long windows. Use `observe` only for side-by-side comparison or short retained windows where direct comparison is needed.
- When Layer2 prunes a few irrelevant chunks from a long video, keep the remaining chunk windows and re-check only those. Do not collapse a long retained video into one sparse 8-12 frame `observe`.
- Use similar or slightly lower frame density than Layer1 for broad retained scans, but preserve chunked coverage. The point is to drop unnecessary chunks, not to stop chunking altogether.
- The Layer2 prompt must include a concrete checklist derived from Layer1, not generic "look carefully" instructions.
- Use Layer1's `temporal_index` to choose retained windows. If Layer1 did not localize a needed event, Layer2 should ask the VLM to produce or refine that index before broad high-frame focus.
- When re-checking a Layer1 chunk, copy the exact seconds from that chunk label. For example, if Layer1 says `[Chunk 2/7 (85s-171s)]`, the Layer2 target must use that same `[85, 171]` window, not the next chunk. If a Layer2 result contradicts Layer1, first verify that the same video and same time window were inspected before overturning Layer1 evidence.
- Do not overturn a high-confidence Layer1 finding using a Layer2 result from a different window, lower-coverage sample, or generic absence statement. Use Layer2 contradictions to refine or request focused verification unless they inspect the same evidence window with stronger direct evidence.
- Required memory update:

### Focus Compare: predict -> observe -> reply
Goal: resolve one concrete uncertainty with denser evidence.
- Before each focus call, state a hypothesis and a competing alternative in `thought`.
- Predict what visual evidence should appear for each interpretation.
- Focus only the minimal necessary targets/chunks: usually 1-2 targets, never broad full scans.
- Focus normally uses `observe`, because it compares specific windows side-by-side or inspects one narrow window densely.
- Increase frame density over Layer2 for the same time/window because this is detailed verification:
  - standard video focus: usually 16-32 frames per target;
  - short clips or PSS pair focus: 12-16 can be enough;
  - UAV focus: 24-32 frames per synchronized view when tracking/occlusion matters.
- Narrow the time/frame window. Prefer exact candidate chunks found in Layer1/Layer2 over whole-video focus.
- Every focus call should cite the `temporal_index` window it is using. If no indexed window exists, first use Layer2 to locate one unless the full clip is already very short.
- Focus prompts must be symmetric: define evidence for hypothesis A and evidence for hypothesis B, then ask for contradiction checks.
- Do not infer cross-target chronology from display order. The executor concatenates frames only for display; preserve local time/window evidence and use visible state transitions for temporal reasoning.
- If focus contradicts earlier memory, use `MODE=focus BACKTRACK` and update `resolved_uncertain`.
- After focus, update:
  - `confirmed` or `resolved_uncertain`;
  - remaining `uncertain`;
  - `object_memory` / `comparison_table`;
  - whether another focus is needed before answering.

### Answer

- If confidence is 7/10 or lower, or if no numeric confidence is available, do not answer from Layer1; run Layer2/focus.
- Otherwise, run Layer2/focus before answering.
- `thought` must summarize only decisive evidence and close rejections.
- `final_answer` must contain only the required answer format from the task contract.
- For multiple-select and ordering tasks, count/check all required indices or letters before answering.

## Temporal Retrieval Index
Maintain a lightweight retrieval index so later stages focus on specific chunks instead of full videos.
- For standard videos, use seconds: `[start_time, end_time]`.
- For UAV/image-folder tasks, use frame indices: `[start_frame, end_frame]`.
- For PSS, each clipped segment's local time starts at 0; record the local window inside that segment.
- For PSS and other shuffled-video tasks, `temporal_index` windows are local retrieval pointers only. They are not global timestamps and must never be compared across different `video_index` values to infer order.
- Index only useful windows:
  - `candidate_windows`: likely answer-relevant moments;
  - `decisive_moments`: narrow events that could prove/reject an option or ordering edge;
  - `irrelevant_windows`: windows already checked and unlikely to matter.
- Each indexed item should keep the original field names: target/video/view/segment id, `window`, `event`, `key_objects`, `visible_state`, `why_it_matters`, and `confidence` (`high`, `medium`, or `low`). Compress field values, not field names.

## Negative Evidence Rules
Be precise about absence.
- Use `ABSENT` only when the sampled window covers the relevant stage/location and the object/action should be visible if present.
- Use `NOT_VISIBLE_IN_THESE_FRAMES` when the current frames do not show it, but the sampled window may not cover the relevant moment or camera view.
- Use `UNCERTAIN` when the detail would affect the answer and the frames are ambiguous, occluded, blurred, too sparse, or outside the relevant window.
- Do not convert `NOT_VISIBLE_IN_THESE_FRAMES` into a global negative conclusion. If it matters, add a `temporal_index` gap and focus plan.
- If earlier context reported an object/action but current frames do not show it, write `NOT_VISIBLE_IN_THESE_FRAMES - possibly in another indexed window` rather than directly contradicting prior evidence.

Each relation may use one of these evidence types: `direct_transfer`, `same_object_state_progression`, `visible_completion_to_next_start`, `caption_temporal_cue`, or `focused_visual_tie_break`. Do not use evidence types like `recipe_logic`, `common_sense`, `typical_order`, `coarse_role_only`, or `sounds_later`.
